# Basic Flow

- There are mainly two ways to upload file/image on s3
  1. Frontend sends file/image to backend and then backend uploads it on s3.
  2. Backend gives a pre-signed URL to frontend and then frontend uses it to directly upload file/image on s3.
- In 1st way, since the file/image is first sent to backend, it is slower and it also increases server load when file size is large. Also it is expensive as each request to backend server has a cost.
- In 2nd way, uploads are faster because we are directly sending file/image to s3. Thus backend stays lightweight.
- This basic flow of 2nd way is as follows -
  - Frontend selects a file/image and requests backend for a pre-signed URL using a POST request.
  - Backend connects with AWS S3 and gets a pre-signed URL. It then sends it back to frontend. It also sends the fileURL, a URL to access file directly(if bucket is public).
  - Frontend then uses that pre-signed URL to upload the file/image to s3.
  - Upon successfull upload, frontend send the fileURL to backend and backend stores it in DB.

# Create S3 bucket

- We go to our AWS account and search for Amazon S3.
- Then we create a bucket with details like name, region etc.
- If we set the bucket as public, anyone can directly access our files using fileURL. If set as private, files can be accessed only via pre-signed URL.
- For now we will set it as piblic.

# Create IAM User

- Inside AWS, search for Identity and Access Management(IAM).
- Create IAM User, with details like username etc etc.
- Attach policies(set permissions). Attach 'AmazonS3FullAccess' (for now its fine, but in production we give more specific access to s3)
- After IAM User is created, we create access key(Access Key ID and Secret Access Key) for it. This is done by selecting the IAM User.
- Store Access Key ID and Secret Access Key in env of backend.

### Note:

- IAM User is a seperate identity(user) created inside an AWS account with specific permissions.
- The root user(the one with the AWS account) has full access to all the services of AWS like s3, EC2 etc etc.
- An IAM user has specified access to specified services, like for eg. a particular IAM User has only upload access on s3.
- We can create multiple IAM Users inside a single AWS account with different different permissions.
- Every IAM User has an Access Key ID(like mailid) and a Secret Access Key(like password). These are credentials of that particular IAM User.
- Policies can be attached to an IAM user at creation time or later. They specify the permissions that determine which AWS services and resources the user can access.

## src/utils/generateFileName.js

```
const { randomUUID } = require("crypto");

const generateFileName = (fileType) => {
  const extension = fileType.split("/")[1];
  return `${randomUUID()}.${extension}`;
};

module.exports = { generateFileName };
```

## src/controllers/upload.controller.js

```
const { PutObjectCommand } = require("@aws-sdk/client-s3");
const { getSignedUrl } = require("@aws-sdk/s3-request-presigner");
const { s3 } = require("../config/s3.config");
const { generateFileName } = require("../utils/generateFileName");

const generateUploadUrl = async (req, res) => {
  try {
    const { fileType } = req.body;

    const fileName = generateFileName(fileType);

    const command = new PutObjectCommand({
      Bucket: process.env.AWS_BUCKET_NAME,
      Key: `uploads/${fileName}`,
      ContentType: fileType,
    });

    const uploadUrl = await getSignedUrl(s3, command, {
      expiresIn: 60,
    });

    const fileUrl = `https://${process.env.AWS_BUCKET_NAME}.s3.${process.env.AWS_REGION}.amazonaws.com/uploads/${fileName}`;

    res.status(200).json({
      success: true,
      uploadUrl,
      fileUrl,
    });
  } catch (error) {
    console.log(error);

    res.status(500).json({
      success: false,
      message: "Failed to generate upload URL",
    });
  }
};

module.exports = { generateUploadUrl };

```

### Note:

- new PutObjectCommand() lets us create an upload command object containing bucket and file related details. We use it to get upload pre-signed url from s3
- getSignedUrl() is used to get a pre-signed url from s3. We pass s3 object in to provide connection details to s3, and command object to provide bucket and file related details to s3.
- We also pass an extra object for additional details like expiresIn(after how time, pre-signed url will expire)
- AWS first verifies the request using Access Keys present in s3 object. If the IAM User is invalid or does not have permission to upload file, request will be blocked.
- If everything is fine, it returns back the pre-signed url.
- Before understanding why we created fileUrl like that, lets first understand how S3 stores files.
- S3 does not store files in a folder type structure. It stores them as key-value pair.
- Every file is stored as (bucket_name, key).
- If the bucket is public, the file can be accessed using the url - `https://<bucket_name>.s3.<region>.amazonaws.com/<key>`
- While creating command object, we specify bucket name and key. Thus the pre-signed url that we get using that command object stores any file as (our_bucket_name, upload/filename).
- So the fileURL of any file becomes - `https://our_bucket_name.s3.our_region.amazonaws.com/upload/filename`. This is the same fileURL that we are manually creating.
- If the bucket is public, anyone can access a file using its fileURL.
- Both of these are sent back to frontend and now frontend can use this pre-signed url to upload any file.

# Additional Bucket settings

- Intially we will not be able access our bucket to upload and get file because of S3 CORS error.
- To configure S3 CORS -
  - Go to your bucket in Amazon S3
  - Go to Permissions tab
  - Scroll to CORS configuration
  - Click Edit
  - Add this:
  ```
  [
  {
    "AllowedHeaders": ["*"],
    "AllowedMethods": ["GET", "PUT", "POST"],
    "AllowedOrigins": ["*"],
    "ExposeHeaders": []
  }
  ]
  ```
- AllowedOrigins: Who can send HTTP requests to S3. For now its everyone, later we can put our frontend domain
- AllowedMethods: Which HTTP methods(GET,PUT,POST,DELETE) are allowed in the requests to S3.
- AllowedHeaders: Which HTTP headers(Content-Type etc etc) are allowed in the requests to S3.
- ExposeHeaders: optional
- After this, we will be able to upload file on s3.
- Now even though we have made our bucket public, we can't access files stored in it because we have not set bucket policy.
- To set bucket policy -
  - Go to your bucket in Amazon S3
  - Go to Permissions tab
  - Scroll to Bucket policy
  - Click Edit
  - Add this -
  ```
  {
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicRead",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::bucket_name/*"
    }
  ]
  }
  ```
- In Resource field, bucket_name is the name of our bucket.
- Adding this bucket policy allows everyone to access files stored in our bucket now.
